# 03 - System Design (Iteration 2)

Stage 3. Reads `02-pm-roadmap.md` (binding thresholds in section 2 there; this file only names keys and formulas), `01`, `00`, and existing code (`schema.prisma`, `links.module.ts`, `sync.service.ts`, `reservations.module.ts`, `ai.module.ts`, `auth.guard.ts`, `seed.ts`). Stack: NestJS + Prisma + PostgreSQL, Next.js. All thresholds are read from `platform_settings` via `SettingsService.get(key, default)`; defaults in section 6.

## 1. System Design
- **Scope**: map explorer, interaction tracking/hot, telemetry + incident detection, performance score, tickets, seller insights, add-on catalog, demo incident injection. Out: add-on purchase, alerts, repricing, public operator ranking.
- **Reused as-is**: `AuthGuard` + `@Perms/@Roles` (perms come from the JWT), `OperatorContext`, `LedgerService`, `PricingService.compute`, `SyncService` scheduler. Nodes are not a table: a node = normalised city name (`lower(trim(originName|destinationName))`) of ACTIVE links of APPROVED operators.
- **Visibility base filter** (all public reads): `deletedAt=null, status=ACTIVE, operator APPROVED`. Suspended operator => links vanish from explorer/marketplace; tickets stay readable by their parties.
- **Demo rows**: `isDemo` on `LinkInteraction`, `LinkMetricSnapshot`, `LinkTicket`, `Reservation` (seed only). Excluded from every aggregate when `demo.countInMetrics=false`; API always returns `basis.includesDemo:boolean` so UI shows the badge.

## 2. Flows (text spec)
1. **Explore**: web loads `GET /explorer/graph` -> draws nodes/edges -> user clicks A, then Z -> `GET /explorer/routes` -> list; server records SEARCH (unmet=true if 0 routes with capacity) -> UI shows "no capacity" state.
2. **Telemetry**: scheduler -> `runSync` -> `ingest` -> per link `upsertLink` -> (telemetry present and last snapshot older than `telemetry.pollMinutes`) insert `LinkMetricSnapshot` (written BEFORE the checksum no-op early return; telemetry is excluded from the checksum) -> `IncidentDetector.evaluate(linkId)` -> open/escalate/auto-resolve SYSTEM ticket -> ledger TICKET.
3. **Ticket**: buyer/operator POST -> OPEN (due times stamped) -> operator ACK -> IN_PROGRESS -> RESOLVED -> buyer confirms or sweeper auto-closes -> CLOSED. Each transition = ticket update row + ledger row in one transaction.
4. **Score**: `PerformanceService` batch (50 links/run) every `perf.recomputeMinutes` or on `POST /admin/quality/recompute` -> upsert `LinkPerformance` -> read APIs.
5. **Insights**: cron/`POST /seller/insights/generate` -> facts engines (deterministic) -> optional narrative -> persist `SellerInsightReport` -> ledger INSIGHT.
- **Exception flows**: operator API down => no sample (never an outage ticket; surfaces as stale-sync insight); planned maintenance => samples neutral; LLM failure => report saved with `engine:"rule-based"`; ledger append failure on tickets => transaction rolls back (use `ledger.append`, not `appendSafe`, for ticket events).

## 3. Architecture
Modular monolith (as existing). Read-heavy endpoints use set-based SQL (`$queryRaw` with `FILTER`, `percentile_cont`, `stddev_samp`) and in-memory TTL cache keyed by setting `explorer.cacheSeconds`; no new infrastructure. Env: `DEMO_MODE` only gates seed + mock incident injection (also requires setting `demo.incidentInjection=true`).

## 4. API contract

Errors: `{statusCode, code, message, details?}` with stable `code` (e.g. `NODE_NOT_FOUND`, `TICKET_NOT_RENTER`, `TICKET_STATE_CONFLICT`, `INSUFFICIENT_EVIDENCE` is NOT an error - it is a 200 state). Out-of-scope resource => 404 (never 403) to avoid existence leaks. Pagination: `page,pageSize<=50` => `{items,total,page,pageSize}`.

## 5. Algorithms
Notation: `W`=window; `now` UTC; day bucket = date in `platform.timezone`; demo rows filtered per section 1.

**5.1 Interaction record** (`record(userId,type,{linkId?,from?,to?})`): `routeKey = sort(nodeKey(from),nodeKey(to)).join('|')` or derived from link endpoints. `counted=false` if the actor is ADMIN or owns the target link's operator. Else try insert with `countedKey = userId|(linkId ?? routeKey)|type|day` (UNIQUE) ; on P2002 insert same row with `countedKey=NULL, counted=false` (raw rows always kept; race-safe; cap=`hot.perUserDailyCap`=1 by construction).

**5.2 Hot** (per target T = link, or direct node pair): `S_cur = sum(w[type])` over counted rows in `[now-7d, now)`, `S_prev` over `[now-14d, now-7d)`, `n` = counted rows in current window; `trendPct = S_prev>0 ? (S_cur-S_prev)/S_prev*100 : (S_cur>0 ? 100 : 0)`; `scarcityPct = availableMbps/capacityMbps*100` (route = sum over its direct links; null if capacity unknown). **hot = n >= hot.minEvents AND S_cur >= hot.minScore AND (trendPct >= hot.minTrendPct OR scarcityPct <= hot.scarcityPct)**. Pair events = events with that `routeKey` plus link-level events of its direct links (each row once). Multi-hop routes are never hot; legs carry their own link flag. One grouped SQL (`count(*) FILTER`) per request, cached 60s. Ranking = hot targets by `S_cur` desc, top `explorer.hotRankingLimit`.

**5.3 Unmet demand**: SEARCH rows with `unmet=true` (set at record time by explorer: 0 eligible routes at `minMbps`). Per seller: unmet routes where an endpoint node is one of the seller's nodes and seller has no AVAILABLE link covering that pair; count only counted rows; item shown only if n >= `insight.minEvidence`.

**5.4 Congestion**: `u_now = 100*(1-availableMbps/capacityMbps)` (null if either missing => "no data"); level HIGH `>=congestion.highPct`, WARN `>=congestion.warnPct`. Sustained: snapshots in last `sustainHours` count>=3, span>=0.8*sustainHours, all `utilizationPct>=warnPct` => WARN (HIGH if all >=highPct). **Slope/days-to-saturation**: daily mean utilization over `congestion.forecastDays`; require >= `congestion.minPoints` days; OLS slope `b` (pct/day); `if b >= minSlopePctPerDay: daysToSat = (100-u_last)/b`, report if `<= congestion.horizonDays`, labelled "indicative", with `r2` and `points`; else omit.

**5.5 Performance score** over `perf.windowDays` (samples with at least latency or status). Evidence: `samples >= perf.minSamples` AND `coverageDays=(maxAt-minAt)` days `>= perf.minCoverageDays`, else not rated. Components (0-100, `clamp` to [0,1] before scaling): `latency = 100*(1-clamp((p95/p50-1)/perf.latencyP95Tolerance))`; `availability: A=100*(1-outageMin/(windowMin-plannedMin)); 100*clamp((A-perf.availabilityFloorPct)/(100-perf.availabilityFloorPct))`; `tickets = 100*(1-clamp(0.5*breachRate+0.5*min(1,nBuyerOperatorTickets/perf.ticketCap)))` (SYSTEM tickets excluded from count to avoid double-counting outages, included in breachRate); `headroom = 100*clamp((100-u_p95)/perf.headroomFullPct)`; null if no utilization. **score = round(sum(w_i*c_i)/sum(w_i over non-null c_i))**, weights `perf.weights` (default latency .30, availability .40, tickets .20, headroom .10); availability and latency components mandatory. `outageMin` = overlap of SYSTEM OUTAGE incident intervals `[incidentStartAt, incidentEndAt ?? now]` with window (measured only; reported tickets never change availability). SLA availability breach: `A < (link.slaPercent ?? sla.defaultAvailabilityPct)` over `sla.windowDays`.

**5.6 Ticket KPIs** (tickets created in window, no demo if excluded): `MTTA = avg(ackAt-createdAt)` over acked; `MTTR = avg(resolvedAt-createdAt)` over resolved; due times at creation: `ackDueAt=createdAt+ticket.sla[sev].ackMin`, `resolveDueAt=createdAt+...resolveMin`; sweeper sets `ackBreachedAt`/`resolveBreachedAt` when `now>due` and not yet ack/resolved (ledger `ticket.sla.breached`, once); on transition breach also flagged if `ackAt>ackDueAt`. **breachRate = tickets with any breach flag / tickets with (resolved or past resolveDue)**; planned-maintenance overlap excluded (ticket skipped if `incidentStartAt` inside a maintenance sample span). Shown only if count >= `ticket.minForRates`.

**5.7 Auto-ticket detection** (`evaluate(linkId)` on each new snapshot). Classify each sample: `OUTAGE_BAD` = `status=DOWN` or `lossPct>=perf.outageLossPct`; `DEGRADE_BAD` = not outage and (`status=DEGRADED` or `lossPct>perf.lossDegradePct` or `latency>perf.latencyDegradeFactor*baseline`), baseline = p50 latency of samples 7d prior to the last 3 (skipped if < `perf.baselineMinSamples`); `PLANNED` (`plannedMaintenance` or link MAINTENANCE) = neutral/skipped; else GOOD. Rules on the latest non-neutral samples: (1) last `perf.outageMinSamples` all OUTAGE_BAD => OUTAGE; (2) else last `perf.degradeMinSamples` all bad => DEGRADATION; `incidentStartAt` = first sample of the streak. (3) **Dedup**: at most one open SYSTEM ticket per link (partial unique index; race loser catches P2002 and reads existing); DEGRADATION open + outage streak => escalate in place (kind OUTAGE, severity from `ticket.severityMap`, due recomputed from `createdAt`, update row `escalated`). (4) **Flap guard**: SYSTEM ticket of same kind resolved < `ticket.flapWindowMin` ago => reopen it (`flapCount++`) instead of new. (5) **Auto-resolve**: open SYSTEM ticket and last `ticket.autoResolveSamples` samples all GOOD => RESOLVED, `incidentEndAt=resolvedAt=` first good sample time, actor SYSTEM, ledger `ticket.auto_resolved`. Auto severity: `ticket.severityMap` (OUTAGE SEV1, DEGRADATION SEV2).

**5.8 Route search** (undirected simple paths, <= `min(maxHops, explorer.maxHops)`): eligible links = base filter AND `availability=AVAILABLE` AND (`minMbps` unset OR `availableMbps>=minMbps`). Build adjacency of nodes; BFS from Z gives `distToZ`; DFS from A prunes when `depth+distToZ[node]>maxHops`; per edge keep top `explorer.maxParallelPerEdge` links by `priceFrom`; stop at `explorer.maxRoutes`. Route = node path; summary: `priceRange=[sum of per-leg min, sum of per-leg max]` (sum of legs, not a quote), `bestLatency=sum of per-leg min` (null if any leg null), `availableMbps=min over legs of max candidate availableMbps`, `performance.minScore` = min over legs (any leg unrated => `rated:false`). Sort default: hops asc, priceRange.min asc. `priceFrom = PricingService.compute(link,rules,{termMonths:12}).unitPrice` (same as marketplace); compare prices only within same currency/priceUnit. Promos: active `PROMOTION` rules (`isActive`, valid dates) for legs' links or operator-wide, plus `promo.platform` setting entries.

**5.9 Insights** (own operator, window `insight.windowDays`; each item needs `n >= insight.minEvidence`, else `{insufficient}`). *Demand*: topSearched = SEARCH counts per own link/route; bestSelling = RESERVE counts + new PAID/CONFIRMED items; rising = trendPct >= `hot.minTrendPct`; congestionRisk = 5.4. *Add-ons* (needs >= `insight.minRentedLinks` rented own links): rentals = items in PAID/CONFIRMED reservations on own links; each rule in `insight.addonRules` (`{kind,when:{maxRedundancy?,minUtilPct?,availabilityBelowSla?,categoriesIn?,minRentedLinks?}}`) evaluated per rented link; output `{kind,matchedLinks,renterCount (count only, no identity),catalogAddOnId|null,action:"LIST_ADDON"|"CREATE_ADDON"}`. *Improvements* codes: `LOW_UPTIME`, `LATENCY_UNSTABLE`, `PRICE_OUTLIER` (price/Mbps vs route median over >= `insight.minPeers` links same route, `|dev|>insight.priceDeviationPct`, direction above/below), `STALE_SYNC` (`now-lastSyncedAt > quality.staleSyncHours`), `NO_KMZ`, `NO_TELEMETRY` (no telemetry snapshot in 7d), `SLA_BREACHES`, `LOW_SCORE`; each carries evidence + bilingual text from a template map keyed by code. Narrative: `AiService.complete` receives facts JSON only; engine label per report; numbers never come from the LLM.

## 9. Edge cases and performance
- Null capacity/availability/latency => "no data", never 0; no links => empty graph (no fake nodes); node names with different casing/whitespace merge by `nodeKey`; A=Z => 400; multiple parallel links per pair; deleted link with open ticket keeps ticket (sweeper still auto-closes); operator suspended mid-incident => detector skips (link hidden); sync returning stale/duplicate timestamp => insert skipped when `recordedAt <= last`; clock jumps => `recordedAt` taken from server time unless adapter timestamp is within 5 min.
- Hot gaming: per-user/day cap, seller+admin exclusion, throttle, only server-side CART_ADD/RESERVE (cannot be forged). Unauthenticated reads are not tracked.
- Ticket leakage: scope filter inside the Prisma `where` (not post-filter); buyer tickets filtered by `reporterUserId`; `/links/:id/tickets/summary` returns no text/ids; insight endpoints derive `operatorId` from token (admin-only override).
- Performance: explorer graph = 2 queries (links+rules, grouped interactions) then in-memory; route DFS bounded by hops/maxRoutes/maxParallelPerEdge; performance recompute batched, SQL aggregates, `perf.recomputeMinutes`; marketplace uses one batch `LinkPerformance` read (no N+1); snapshots ~96/link/day at 15 min => retention + index on `(networkLinkId,recordedAt)`; interaction write is single insert (+1 on conflict), fire-and-forget (`void promise.catch(log)`), never blocks the request.
- Settings malformed/missing => fall back to defaults in section 6 (log warn); `perf.weights` not summing to 1 => normalised.
