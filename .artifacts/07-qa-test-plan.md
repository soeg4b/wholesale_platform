## 1. Test Plan
- **Scope in**: the 4 requests (R1 explorer, R2 seller AI, R3 performance + tickets, R4 pipeline artifacts), RBAC/tenant isolation, thresholds, demo flag, i18n, bilingual text. **Out**: payments, auth internals, add-on purchase, alerts, real operator telemetry, load beyond 500 links.
- **Quality gates**: 0 open High; Medium defects accepted only with owner + date; smoke green; every threshold boundary tested on both sides; no cross-tenant read (ticket, insight, add-on, interaction audit); every user-visible string present in ID and EN.
- **Levels**: unit (Vitest; none installed yet: no `*.spec.*`, no vitest/jest/supertest/playwright in either `package.json`), integration (Supertest on Nest app + test DB), system (`scripts/smoke.mjs` + new boundary script), E2E (Playwright: buyer, operator, admin), regression (ledger chain, reservation flow, link search).
- **Environment/data**: Postgres with `prisma/sql/*.sql` applied (partial unique indexes, CHECKs, `link_latency_stats`); seed + seed-demo; API :4000, web :3000; mock operators; clock control via fake timers for sweeper/detector; settings reset between tests (`platform_settings` edits invalidate after 15 s cache: `settings.service.ts:15-26`). Existing JWTs predate new perms (`ticket:create` etc.): re-login required.
- **Coverage matrix**: Unit = hotInfo, classify, scoring maths, route DFS, transitions, congestion regression. Integration = every endpoint x role. System = incident inject -> ticket -> recover. E2E = explore A->Z, report issue, ticket lifecycle, insights tab, language toggle.

## 2. Code Quality Review
- **Structure**: one file per module (explorer 545 lines, tickets ~700, insights ~860) mixing service + controller; acceptable for MVP; `tickets`/`insights` should split service files before iteration 3. Settings-driven thresholds are consistent; no hardcoded thresholds found.
- **Security**: tenant scoping is in the Prisma `where` (good: `tickets.module.ts` `scopeWhere`). Gaps: D01, D05, D08, D12, D14 below. No SQL injection (tagged templates only). Mock operator + demo seed overrides ship without env guard (D18).
- **Performance**: D10 (N+1), D17 (platform-wide peers load per insight run), sequential detector loop in admin recompute (`quality.module.ts:335`).

## 3. Validation Framework
- **Pass/fail**: a test passes when status code, `code` field, body shape and side effects (ledger row, ticket update row) all match SA section 4; any 5xx on client input is a fail.
- **Severity**: High = wrong data to users, 5xx on valid-looking input, data leak; Medium = wrong KPI/UX state with workaround; Low = cosmetic/i18n. Priority P1 fix before Tester sign-off, P2 before release, P3 backlog.
