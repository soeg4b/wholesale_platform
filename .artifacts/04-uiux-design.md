# 04 - UI/UX Design (Iteration 2)

Stage 4. Reads `03-sa-system-design.md` (API shapes, states), `02-pm-roadmap.md` (thresholds/visibility), `00-iteration2-brief.md`, and existing web code. Fits current conventions: dark slate theme, `.card/.btn-*/.input/.label/.badge/.th/.td`, `brand-500`, `Status` badge, `ErrorNote`, `RequireRole`, `t()/tr()` from `lib/i18n`, Leaflet via `components/Map.tsx` (dynamic, no SSR), operator tab bar pattern (`border-b-2 border-brand-500`). No new design system, no new colour tokens.

## 1. UX Strategy Summary
- **Goals**: buyer finds A-to-Z capacity in <= 2 clicks and judges trust (score, tickets, hot, promo) before opening a link; seller sees what to act on (demand, congestion, add-ons, fixes) and works tickets inside SLA; admin audits.
- **Principles**: evidence always visible (basis line, "Not yet rated", "Insufficient data", Demo badge); never show a fake 0 or default-good; colour is never the only signal (icon + text + line style); keyboard parity (map click == select); all strings via `dictionary.ts`; server-provided `{id,en}` text rendered with `tr()`.
- **Assumptions**: nodes/edges come only from `GET /explorer/graph`; thresholds never in UI (SA keys); straight edge lines are connectivity, not physical routes (real KMZ stays on link detail).

## 2. Explorer `/explore` (default landing for logged-in users; Navbar first item `nav.explore`; `/` redirects here; `/marketplace` stays as list view, reachable via "Lihat sebagai daftar" with `origin/destination` prefilled)
**Desktop (>= lg)**: full-height row under the navbar: map `flex-1` (`h-[calc(100vh-57px)]`) + right panel `w-[400px]` (md: `w-[340px]`) `overflow-y-auto border-l border-slate-800 bg-slate-950`. A floating selector bar sits top-left on the map (`absolute z-[500] card p-3 flex gap-2`): `[A-End select] [swap] [Z-End select] [Min Mbps input] [Clear]`. Legend (collapsible `<details>`) bottom-left.
**Mobile (< md)**: stacked. Selector card (selects stacked, swap between) -> map `h-[45vh]` -> panel as normal flow with sticky tab strip `Routes | Hot | Promo` (`sticky top-[57px]`). Touch targets >= 44px (`min-h-11`). Tablet (md): map + 340px panel side by side, selector bar wraps to two rows.

**Encoding (always paired with a non-colour cue; legend lists all)**
| Element | Visual | Non-colour cue |
| --- | --- | --- |
| Node | `CircleMarker` r = 6 + min(linkCount,6); fill `#38bdf8` if any edge has `availableCount>0` | no capacity = hollow ring (fillOpacity 0, 2px stroke) |
| Node A / Z | A: emerald `#34d399` ring + permanent tooltip "A"; Z: violet `#a78bfa` + "Z" | letter label, bigger radius (+4) |
| Edge available | solid `#38bdf8`, weight 2-6 by `linkCount` | solid line |
| Edge no capacity | `#64748b`, `dashArray "6 6"`, weight 2 | dashed |
| Edge hot | `#fbbf24`, weight +2, midpoint `divIcon` pill "HOT" with flame SVG | text pill, thicker |
| Selected route (hover/focus a route card) | `#34d399` weight 6 over its legs; others dim to opacity .25 | thicker + dim others |
Edge tooltip/popup: `A - B`, links, available Mbps, from price, best latency, HOT + trend %. Multi-hop edge highlight uses dashed + "Indikatif" tooltip.

**Selection (A then Z)**
- Click node: no A -> set A; A set, no Z, node != A -> set Z and fetch routes; both set -> replaces Z; click A again -> unset A (Z kept, routes cleared until A chosen). Changing A when both set: use the A select or the A chip `x`.
- Selector bar is the canonical, accessible control: two native `<select>` ("A-End", "Z-End"), options = `nodes` sorted by name with `(linkCount)`; A option equal to Z disabled (client guard for `SAME_NODE`). `Swap` (aria-label `explore.swap`) swaps and refetches; `Clear` resets A, Z, routes (also `Esc` on map). `aria-live="polite"` region announces "A-End: Jakarta. Z-End: Surabaya. 4 rute ditemukan".
- Keyboard: nodes are `L.marker` with `divIcon` (`keyboard:true`, `role="button"`, `aria-label="Jakarta, 6 link, pilih sebagai A-End"`); Tab to focus, `Enter/Space` selects (same logic as click). The selects remain the guaranteed fallback if map focus is awkward.
- State in URL (`?from=&to=&minMbps=`) so views are shareable and Back works; invalid key -> `NODE_NOT_FOUND` -> clear selection + inline note `err.NODE_NOT_FOUND`.
- Refetch routes on A/Z/minMbps (debounce 400ms for minMbps); sort select `price|latency|score|hot`.

**Panel by state**
1. *No selection*: title `explore.title`, hint `explore.pickA`; **Hot ranking** list (top `hotRankingLimit`; row = name, score, trend `+x%` with up-arrow icon, click focuses edge on map); **Promos** (see open Q1). Empty: `explore.hot.none`.
2. *A only*: chip A, hint `explore.pickZ`; nodes with a direct edge from A pulse-ring (`animate-pulse`, motion-reduce safe).
3. *A+Z loading*: 3 skeleton cards (`animate-pulse bg-slate-800 h-28 rounded-xl`) + map overlay spinner text `common.loading`.
4. *Routes*: header `n routes`, "Demo data" badge if `basis.includesDemo`, sort + view-as-list link. Each **RouteCard** (`card p-4`, focusable `<li><button>`, hover/focus highlights map): row 1 hop badge (`Direct` / `2 hops`), operator names, **Indikatif** amber badge for `indicative` + one-line disclaimer `route.indicativeNote` ("jumlah per segmen, bukan penawaran; tanpa jaminan ujung-ke-ujung"); row 2 price range `Rp min - max /bln` (same currency only; mixed currency -> "per segmen"), best latency, available Mbps (`-` + "no data" if null); row 3 badges: HOT (flame icon+text), promo pills (`name`, `adjustment`, "s/d date"); row 4 **capability chips**: add-ons (kind icons+labels), redundancy `min-max%`, SLA `%`, performance chip (score number + 0-100 bar, or `perf.notRated` badge slate), KMZ chip. Expand ("Lihat segmen") -> legs: per leg `from -> to`, candidate rows (operator, priceFrom, latency, available, perf chip, HOT) with `Lihat & sewa` -> `/links/[id]`; note `route.perLegReserve` ("reservasi per segmen").
5. *Unmet* (`unmet:true`): card with icon, "Belum ada kapasitas tersedia A -> Z", suggestions (lower min Mbps, try marketplace), disclosure `explore.unmetLogged` ("pencarian ini dicatat sebagai permintaan"), no fake routes.
6. *Graph empty*: map shown, overlay card `explore.empty` ("Belum ada link aktif"); operator/admin get CTA to `/operator`. *Graph error / routes error*: `ErrorNote` + `btn-ghost` retry; selectors disabled on graph error. 429 `THROTTLED`: inline "terlalu cepat" note, no retry loop.

## 3. Link detail: Performance card and report issue (`/links/[id]`, left column after Specs card)
**PerformanceCard** (`card`): header `perf.title` + badges (`Demo data` if `basis.includesDemo`; `perf.previewOnly` amber "Pratinjau - belum terlihat pembeli" for seller/admin when `previewOnly`).
- *Rated*: big score `82` + `/100` + bar; 4 component rows (latency, availability, tickets, headroom: label, bar, value; headroom hidden if null with "no data"); KPI grid (uptime %, latency mean/p50/p95/stddev, outages count + total minutes, SLA breach flag with icon+text); ticket summary (count, open, MTTA, MTTR, breach % -> each `-` + `perf.insufficient` when null); **basis footer** always: "{windowDays} hari - {samples} sampel - cakupan {coverageDays} hari - diperbarui {computedAt}" and `perf.basisInfo` tooltip on score. Own seller/admin: collapsible outage table (start, end, minutes, source).
- *Not rated* (`rated:false`): slate card, `perf.notRated` + reason text `perf.reason.MIN_SAMPLES|MIN_COVERAGE|NO_TELEMETRY|PREVIEW`, no score, no bar. Loading: skeleton; fetch error: `ErrorNote` (card never blocks the page).
**Report issue (buyer, `PENYEWA`)**: button `btn-ghost` "Laporkan masalah" in the aside under pricing. Opens modal (focus trap, Esc closes, returns focus): `kind` radio (Degradasi/Outage/Lainnya), `severity` select SEV1-3 with description each (default SEV3), `title` (required, <=120), `description` (required, >=20, <=2000, counter), `reservationId` select of buyer's PAID/CONFIRMED reservations on this link (hidden if exactly one; none -> disabled form with `ticket.needRental`). Inline field errors under inputs (`aria-describedby`). Submit -> 201: toast + go to `/tickets/[id]`. Errors by code: `TICKET_NOT_RENTER` -> `ticket.needRental`; `TICKET_DUPLICATE` -> message + link to existing ticket; others -> `ErrorNote`. Operator-type reports use the same modal from the operator Tickets tab ("Buat tiket").
**Buyer tickets** (new nav item `nav.tickets`, role PENYEWA/PENYELENGGARA): `/tickets` list (ref, link, severity, status, updated) and `/tickets/[id]` detail shared by buyer/operator/admin: header + `Status` badge, **stepper** OPEN -> ACKNOWLEDGED -> IN_PROGRESS -> RESOLVED -> CLOSED (current step bold + check icons on done steps, text labels), due times, timeline (`updates`; internal notes never shown to buyers), seller **public reply** block labelled `ticket.publicReply`; buyer actions on RESOLVED: `Konfirmasi selesai` (-> CLOSED) and `Buka kembali` (-> OPEN, needs note), auto-close hint `ticket.autoClose` with hours from setting.

## 4. Operator dashboard (`/operator`) new tabs
Tab type becomes `links|integrations|geo|pricing|insights|tickets|performance|addons`; tab bar gets `overflow-x-auto whitespace-nowrap` and `role="tablist"` (buttons `role="tab"`, `aria-selected`); labels `op.tab.*`. Tabs only fetch when opened. Tickets tab shows a count badge of open tickets.
**Insights**: toolbar: engine badge (`rule-based` / `llm:<model>`), generated-at, window "7 hari", Demo badge, `Generate sekarang` button (disabled while 202 pending; 429 `COOLDOWN` -> disabled + `insight.cooldown`). Optional **narrative** card on top (`narrative[locale]`, labelled "Ringkasan AI - angka dari data, bukan dari model"). Sections as `card` with `<h2>`; each **InsightItem** = text `text[locale]`, severity icon+text, key numbers, and a `Basis` row ("n=42 - 7 hari") with `<details>` showing `evidence` key/values. `{insufficient:true}` -> dashed-border slate card `insight.insufficient` ("Data belum cukup: butuh {needed}, baru {have}"). No report yet: empty state + Generate CTA.
- *Demand*: 4 lists (top searched, best selling, rising with up-arrow + `+x%`, unmet demand routes `A -> Z` count) as ranked rows with counts; *Congestion risk*: row with level badge `HIGH` (red, triangle icon) / `WARN` (amber), utilisation %, and "perkiraan penuh ~N hari (indikatif, r2, n titik)" or `no data` when utilisation null.
- *Add-on opportunities*: row `kind`, matchedLinks, `renterCount` ("N penyewa", no identity); button by `action`: `LIST_ADDON` -> switches to Add-ons tab highlighting the item; `CREATE_ADDON` -> opens add-on form prefilled with `kind`.
- *Improvements*: rows by `code` (LOW_UPTIME ... LOW_SCORE) with link name, evidence, and a deep link (STALE_SYNC/NO_TELEMETRY -> Integrations tab, NO_KMZ -> Geo tab, PRICE_OUTLIER -> Pricing tab, others -> Performance tab).
**Tickets**: filter row (status chips multi-select, kind, source, link select, date range), table `th/td` (Ref, Link, Sev, Kind, Source badge `Sistem/Pembeli/Operator`, Status, **SLA**, Age, Actions); mobile = stacked cards. **SlaCountdown**: shows the next due (ack if OPEN, else resolve) as "sisa 1j 05m" updating every 30s (no live-region announcements); breached (`*BreachedAt` set) -> red + alert icon + "Terlambat 12m"; resolved/closed -> "Dalam SLA" / "Melanggar SLA" text. Default sort: breached first, then soonest due. Row click -> right drawer (same detail as `/tickets/[id]`) with timeline, internal note, one public reply (409 `REPLY_EXISTS` -> shown as already replied). **Actions** render only legal transitions for the status (Acknowledge, Start, Resolve (note required), Reopen n/a for operator after close); optimistic UI off: on 409 `TICKET_STATE_CONFLICT` refetch + toast. SYSTEM tickets show `ticket.system` badge and auto-resolve note.
**Performance**: sortable table of own links: Link, Score (or `Belum dinilai`), Uptime %, p95 latency, Outages (count/min), Open tickets, MTTA, MTTR, Breach %, SLA flag, Basis (samples/coverage), Preview badge. Rows expandable to component bars + outage list. Mobile: cards. Null rates `-` with `perf.insufficient` tooltip. Data: see open Q2.
**Add-ons catalog**: table (kind icon+label, name by locale, price+unit, categories, active toggle `role="switch"`, edit/delete) + `Tambah add-on` modal: `kind` select, name ID + EN (both required), description ID + EN, price, priceUnit, currency, applicable categories (checkbox group), active. Delete = confirm dialog (soft). Empty: `addon.empty` explaining buyers will see chips "ask via reservation note". Buyers never see prices in checkout this iteration (chip only).

## 7. Accessibility (WCAG 2.1 AA)
- Colour never sole: every colour cue pairs with icon/text/line style (section 2); contrast >= 4.5:1 for text on `slate-900` (use `-300` tints as in `Status`); bars carry numeric value text.
- Keyboard: full flow possible with two selects + Swap/Clear + `Enter` on focused markers; visible focus ring `focus-visible:ring-2 ring-brand-500` on cards/markers/buttons (add to `.btn`/RouteCard); modals/drawers trap focus, `Esc` closes, focus returns; tabs support Left/Right arrows.
- Map is not the only path: a11y text summary of nodes/edges is available via selects and the route list; map container `aria-label="explore.mapHint"`.
- Live updates: `aria-live="polite"` for route counts and toasts; SLA ticks silent. Respect `prefers-reduced-motion` (no pulse). Forms: labels bound, errors `role="alert"` + `aria-describedby`. Touch targets >= 44px on mobile. Language toggle changes all strings and `html lang`.
